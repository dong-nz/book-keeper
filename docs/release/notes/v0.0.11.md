# Release v0.0.11 — November 18, 2026

This release renames the application to **Book Keeper**, ships it for **macOS and Linux** as well as Windows, makes its **self-updating real** (every published version now reaches installed apps on its own), and adds an **application log** you can open whenever something went wrong.

## What changed for you

**The name: Book Keeper**

- The application is now called Book Keeper. Same application, same features, same library — only the name changed.

**Installers for Mac and Linux**

- Every release now carries installers for all three platforms: Windows (`.exe` or `.msi`), macOS (a `.dmg`), Linux (a `.deb` or an AppImage). You can download them from the application's releases page, and the app itself fetches its updates from there.
- First run on a Mac shows the usual "downloaded from the Internet" notice — right-click the app and choose **Open** once, and after that it opens normally.

**Updates are real now**

- Until this release, the update feature had nothing real to find: no version had ever been published. Since v0.0.11, every published version is released automatically with its installers and its update information. An installed 0.0.10 will find 0.0.11 the next time it checks — at startup, or through *Check for updates* — and installs it exactly as described in the user guide.

**App logs**

- The app now keeps a plain-text record of things that go wrong: failed actions, files that failed during an import, covers that couldn't be drawn, failed update checks. The Settings window has a **Log** section showing the log file's location with an **Open log file** button, and a level choice: **Error** (the default — problems only) or **Info** (also records the app's normal activity). The log never contains the contents of your documents or your passwords, and it keeps itself to at most two files. The user guide has a full page on it: [App logs](../features/app-logs.md).

**Behind the scenes**

- Every change is now automatically built and tested on Windows, macOS and Linux before it lands — the same tests the developer runs, run on all three systems for every push. Every published release is built the same way, on the same systems. This is what makes the cross-platform installers and the real updates possible, and it makes every future fix safer.

## What this version does not do yet

- The installers carry no purchased store certificate yet, so Windows may show an *"Unknown publisher"* warning the first time you run one: choose **More info → Run anyway**. (A proper signing certificate is a planned candidate, not part of this release.)
- The log has no viewer inside the app — it's a plain text file you open yourself; there's no search or filter.
- The app still doesn't remember where you stopped reading, and right-to-left horizontal reading is still planned for a later release — both unchanged from before.

## Known issues

- The Windows "Unknown publisher" warning and the Mac "downloaded from the Internet" notice are expected first-run behavior of unsigned installers (see above); they say nothing about the app's safety and only appear before the first run.
- The macOS and Linux packages were built, packaged and verified on those systems by the release pipeline itself; their day-to-day behavior on a Mac or a Linux desktop is reported from the same design, and first reports from real machines are expected with the next round of feedback.
- Before this release, the in-app update check reported a failure ("could not check") because no version had been published yet — that was the feature working correctly against an empty releases page. It has something real to find from now on.

Verification for this release: the logging feature's automated flows, the full UI flow suite (62 test lanes, all flows green), the release pipeline proven end to end on all three platforms by a pre-flight release, and a manual review of the app. The full regression pass that covers everything else runs after the release, as usual; anything it finds will be reported and scheduled.
