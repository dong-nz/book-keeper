# Release v0.0.12 — November 19, 2026

This release makes the reader remember you — it returns to where you stopped and keeps your view mode — adds **text selection and copying** in the reader, lets you **choose which page or image represents a document**, and fixes the two problems reported from Macs after the last release. On macOS the app's own window buttons now sit where a Mac expects them.

## What changed for you

**The reader remembers where you stopped**

- Open a document again and it comes back to the page you were last on — including how far down that page you had read. Books return to the chapter and the exact place within it. There is no "go to page" step to redo.
- Removing a document removes its memory; a fresh copy of the same file starts at the beginning. Relinking or renaming a document keeps its place; if a relinked file is shorter, the reader opens at its last page instead of failing.

**Your view mode is remembered**

- The reading mode you last chose (Continuous, Single page, Facing, Continuous horizontal) is the mode new reading windows open in. Nothing chosen before stays as it was: a document you never touched still opens in Continuous.

**Select and copy text**

- In a PDF that carries text, you can now drag across the page to select words and lines and copy them with **Ctrl+C** (or Ctrl+Insert), like anywhere else. The selectable text sits invisibly over the rendered page at the text's real positions — pages look exactly as before, and selection works in every view mode and after zooming.
- A scanned page (one without embedded text) has nothing to select — this release adds no text recognition for scans.
- In books, the text was always real text; it is now selectable and copyable too.

**Choose which page or image is a document's cover**

- Right-click a document and choose **Update cover…** to pick its cover: for a PDF, from a strip of its page thumbnails; for a book, from the images inside it.
- The reader can do the same from where you're reading: in a PDF the cover control offers **"Set this page as cover"** for the page you're looking at; in a book, **"Choose cover…"** opens the book's image grid.
- **"Automatic cover"** puts it back the way it used to be (the first page for a PDF, the book's own cover image for a book). Your choice is kept across restarts, and the chosen cover appears in the list and grid like any other.

**The tags window is tidier, and gained *Delete all tags***

- The tags window now has its own bar with its title and a **Delete all tags** action. Deleting all tags removes the tags themselves — your documents are untouched, just no longer tagged. A confirmation asks first, and the count is reported after.

**On Macs, the window buttons moved**

- The app's minimize/maximize/close buttons now sit at the **left** end of the top bar, close first, like a Mac window's buttons — in the main window and in reading windows. Everything else in the bars stays where it was. Windows and Linux are unchanged. This is still the app's own buttons, drawn in the app's style.

**Fixed: the two Mac problems you reported**

- **The data folder now opens normally.** The folder's name changed (see the note below) — Finder no longer mistakes it for a damaged application, and Settings ▸ Data location ▸ open works on a Mac.
- **The installed Mac app can read PDFs again.** Last week's Mac build could not open any PDF or draw any cover, because it couldn't find its own copy of the page-rendering library inside the installed app. The installed app now finds it. (The Linux ".deb" build had the same problem and is fixed too.)

**Behind the scenes**

- Release and test builds are faster: the Linux setup step reuses a cache instead of re-downloading, and a recent test run now warms the build used to publish a release.

**Important — the data folder has a new name, and this version starts with an empty library**

- The folder is now named **`com.bookkeeper`** (Windows: `AppData\Roaming\com.bookkeeper`; macOS: `Library/Application Support/com.bookkeeper`; Linux: `~/.local/share/com.bookkeeper`). Nothing is moved automatically: if you used 0.0.11, your library stays in the old `com.bookkeeper.app` folder and this version starts fresh and empty. To keep your library, close the app and copy the contents of the old folder into the new one — Settings ▸ Data location shows both folders (the *open* button shows the one actually in use). The old folder is left in place; removing it is your decision.

## What this version does not do yet

- Scanned pages still have no selectable text — no text recognition was added.
- There is no search within a document and no "select all on page" button; a selection is not remembered after you close the reader.
- Cover choice offers only the document's own pages or images — there are no generated title cards.
- Reading position is remembered per document, not per device or account — it lives with your library on this computer.

## Known issues

- On a Mac, **double-clicking the top bar to maximize or restore the window does not work** (single-click dragging the bar works as before). This is a known issue with a fix already designed for a coming release.
- The installers still carry no purchased store certificate, so Windows may show an *"Unknown publisher"* warning on first run (**More info → Run anyway**) and a Mac shows the usual "downloaded from the Internet" notice (right-click → **Open** once).
- After the rename of the data folder, the old `com.bookkeeper.app` folder remains on your disk until you remove it yourself. It is safe to delete once you are happy with the new library.

Verification for this release: the new features' automated flows (remembered position and view mode, text selection in every view mode, cover choice in both readers and the picker, the tags window changes, the Mac button layout), the full UI flow suite, the Rust test suite and lint pass, and seven rounds of manual review of the changed flows in the running app. The full regression pass that covers everything else runs after the release, as usual; anything it finds will be reported and scheduled.
