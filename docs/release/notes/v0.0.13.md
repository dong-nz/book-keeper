# Release v0.0.13 — November 20, 2026

This release changes how the app tells you about a new version: the notice is now a **dialog that shows what's in the new release** and gives you a **Skip this version** choice. On Mac and Linux the app now **restarts itself into the version it just installed**. The bottom bar shows **which version you're running**. And the Mac window-bar problem you reported is fixed: double-clicking the bar maximizes again.

## What changed for you

**A new version is presented as a dialog, with its release notes**

- When a newer version exists, the app now opens a small window instead of a corner notice. It names the version you're running and the newer one, shows that version's release notes, and gives two actions: **Install** and **Skip this version**.
- Closing the dialog without choosing just defers it — the next start asks again.
- **Skip this version** means: stop asking me about *this* version. From then on the startup check runs and stays quiet for the version you skipped. It is not a refusal: **Settings ▸ Check for updates** always shows the skipped version again when you ask, and you can install from there. A newer version than the one you skipped is presented normally.
- **Install** and the download progress work exactly as before.

**After an update, the app restarts into the new version (Mac and Linux)**

- On Mac and Linux, installing used to end with the download done and the old version still running — you had to restart it yourself. Now the app shows a short *"Update installed — restarting"* message and **restarts itself** a moment later, into the new version. Your library and settings are untouched; the app comes back as it was.
- On Windows nothing changes: the app closes, the installer runs, and you open the updated app.
- On Linux, the in-app update works for the **AppImage** version of the app. If you installed the **".deb"** package, you update it the usual way — by installing the new package.

**The bottom bar shows which version the app is**

- At the right end of the bottom bar, in the same quiet style as the document count, the app now shows its own version — for instance **0.0.13**. It's plain text, nothing to click; it's there so you can tell at a glance which version you're using. Everything else in the bar is unchanged.

**Fixed: on Macs, double-clicking the top bar maximizes the window again**

- Double-clicking the empty area of the top bar now maximizes or restores the window, in the main window and in reading windows — the behavior Windows has always had. Dragging the bar with one press works as before, and pressing a button, the search box or a menu still never drags the window. Windows and Linux are unchanged.

**Windows: where the app installs, and one cleanup note**

- The app installs into **your own user account** — no administrator needed — and an update stays exactly where your installation is. One situation can look odd: if your computer carried an older **whole-device** install (installed for all users by an early release), *Settings → Apps & features* shows **two** Book Keeper entries. The one under your account is the live one; the whole-device entry is the stale leftover. Removing it once (that entry → **Uninstall**) leaves a single clean entry. Your library, settings and starred documents are untouched either way — they live in your own data folder, which no install or update writes to.

## What this version does not do yet

- Nothing downloads or installs by itself — a new version is always offered, and installing is your click.
- There is no "never show update notices again" switch — a skip is per version, and asking always re-presents.
- The ".deb" installation on Linux does not update in-app; you install the new package.
- The version in the bottom bar is a label, not a control — updates are still found through *Check for updates*.

## Known issues

- The two Mac changes in this release (double-click maximize, restarting after an update) are built and tested by the app's own automated checks, but their confirmation on real Mac hardware is still open — please report how they behave for you.
- The installers still carry no purchased store certificate, so Windows may show an *"Unknown publisher"* warning on first run (**More info → Run anyway**) and a Mac shows the usual "downloaded from the Internet" notice (right-click → **Open** once).
- If your Windows machine carried the old whole-device install, its stale entry stays in *Apps & features* until you remove it once (see the note above).

Verification for this release: the update flow's automated flows end to end (the dialog with both versions and the notes, deferral, install through the progress bar to the installer, the skip scenario — skipped version silent at the next start, re-presented on demand), the status-bar flow including the version label checked against the packaged version, the window-chrome and drag-region flows re-run unchanged, the settings store's round-trip for the skipped version, the full UI flow suite, the Rust test suite and lint pass, and the manual review of the changed flows in the running app. The full regression pass that covers everything else runs after the release, as usual; anything it finds will be reported and scheduled.
