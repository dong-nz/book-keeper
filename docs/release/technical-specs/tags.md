## Schema (`src-tauri/src/db/mod.rs`)

Since v0.0.8 the schema is one clean baseline at `PRAGMA user_version = 2` (`SCHEMA_BASELINE`, created by a single `execute_batch`):

- `documents(... reading, pdf_password ...)` — the v0.0.8 columns (see [reading-collection.md](reading-collection.md), [password-protected-pdfs.md](password-protected-pdfs.md)).
- `tags(id, name UNIQUE COLLATE NOCASE)` — case-insensitive name uniqueness.
- `document_tags(document_id, tag_id, PRIMARY KEY(document_id, tag_id))` — many-to-many, FKs `ON DELETE CASCADE`.
- `settings`, the FTS table and triggers unchanged in shape.

**No category-named object is ever created** (AC-113): a fresh database runs only the baseline. A database at `user_version = 1` (the v0.0.1–v0.0.7 shape, `categories` / `document_categories`) is upgraded by `UPGRADE_V1_TO_V2`: the two new `documents` columns are added, the clean `tags` / `document_tags` tables are created, rows are copied (`INSERT … SELECT`, ids preserved), the old tables are dropped. No `RENAME` statement exists in the codebase (DR-273 — the user's decision: "clean table create, not altered"; there was no installed user base to preserve through renames).

## Commands

| Command | Behavior |
|---|---|
| `tags_list` | tags with live counts — `LEFT JOIN document_tags` + `GROUP BY`; counts computed in SQL, never cached client-side |
| `tags_create(name)` / `tags_rename(id, name)` / `tags_delete(id)` | delete cascades the join table only; documents are never touched (FR-02) |
| `tags_delete_all` (since v0.0.12, FR-32) | `library::service::tags_delete_all` — `DELETE FROM tags`; every membership detaches by the schema's `ON DELETE CASCADE` (`document_tags`, `foreign_keys` always ON, R2.4); answers the deleted count; an empty library answers 0 — not an error, no new error kind; no document row is touched |
| `library_set_document_tags(document_id, tag_ids[])` | full replace from the Details dialog |
| `library_bulk_tags(document_ids[], add[], remove[])` | add and remove in one transaction (FR-07) |

The v0.0.1–v0.0.7 command names (`categories_*`, `library_set_document_categories`, `library_bulk_categories`, `DocumentDto.categories`) were renamed together with the service/query/db identifiers, error messages, the R1.3 whitelist and the typed client (`api.ts`) — one codebase, no external command consumers (UI-42, AC-113).

## Invariants

- A document may belong to zero or more tags (FR-02).
- **Any number of tag ids may be active as a filter; the SQL is `EXISTS (SELECT 1 FROM document_tags dt WHERE dt.document_id = d.id AND dt.tag_id IN (?, ?, …))` — the union, each document selected once** (FR-02 as modified in v0.0.2). With one id the statement is the single-id path; with an empty list the clause is absent entirely, so the unfiltered query is byte-identical to the no-filter statement.
- The tag set composes with the filter modes (favorites / missing / reading) and with search terms as `(A OR B) AND mode AND terms` — the mode and text clauses are the ones searching.md and reading-collection.md document, never a third path.
- Renaming a tag never changes membership. (Renaming a document's *file* is a different feature — [renaming-a-documents-file.md](renaming-a-documents-file.md) — and preserves tag membership.)
- `last_filter` grammar (settings): `all | favorites | missing | reading` optionally followed by `&tags=<id>(,<id>)*`. The decoder still accepts the legacy forms — `&cats=<id>` (v0.0.2+) and `cat:<id>` (v0.0.1) — so a filter saved before the rename restores with the same groups; new values are written as `&tags=` (`is_valid_filter` / `is_valid_id_list` in `library/service.rs`).

## UI (`ui/src/`)

- Manager: `components/TagsDialog.svelte`, opened from Browse ▸ *Manage tags* (mounted through the shared `Modal` open-binding, DR-63; empty state "No tags yet — create one with Manage tags"). It reuses the released `TagList` / `TagRow` / `NewTagField` components (renamed from their `Category*` names in v0.0.8 — same components, new identifiers) and the renamed `RenameTagDialog` / `DeleteTagDialog`, all following the `DeleteDialog` open-binding pattern (DR-63).
- **Since v0.0.12 the manager is a toolbar dialog (UI-10 MODIFIED, DR-414):** `TagsDialog.svelte` passes the `actions` snippet → the toolbar variant of `Modal.svelte` (the `.modal-toolbar` bar + `.modal-with-toolbar` scroll area — the same variant [covers.md](covers.md) documents for the cover picker: pinned bar, the dialog box itself non-scrolling, full-bleed sides with the scrollbar at the dialog's edges, bottom at the content box clear of the rounded corners, stable gutter, and the 4 px top clearance that keeps the new-tag field off the area's clip edge, DR-415). The bar carries the title, the **Delete all tags** `.control` (disabled while `library.tags.length === 0`) and the close control; the list renders inside `.modal-scroll` — the panel's own `max-height`/`overflow` cap is gone, the area owns scrolling. The per-dialog scrollbar rules and the `:global(.modal:has(...))` box rule added mid-build (DR-413) were deleted with this change; the shape they stated is carried by the shared variant.
- **Delete all tags (FR-32):** `components/DeleteAllTagsDialog.svelte` — the `DeleteTagDialog` confirmation pattern (Discard / danger confirm), body states that documents are kept. The store's `deleteAllTags()` (`state/library.svelte.ts`) invokes `tags_delete_all`, empties the local `tags`, drops every `filter.tag_ids` entry (the released `deleteTag` rule applied to the whole set — a filter left referencing deleted tags would filter to nothing), refreshes the document list, and reports "Deleted N tags" through the feedback path (`toast.tagsDeleted.*`, the i18n plural pattern). No undo (consistent with the single-tag delete).
- **Since v0.0.14 the editor's tags field is a picker (UI-02 MODIFIED, DR-437):** `components/TagPicker.svelte` replaces the `details.fieldTags` checkbox field in `DetailsModal`. The pending set, `baselineIds` dirty tracking and Save stay in `DetailsModal` — the picker is props in/out (`tagIds`, `onchange`, `bind:open`), no new command, no second query path (`DocumentDto.tags` still ships per document, R1.6). Shape: a chips row derived through `chipsFor()` in catalog order (each chip carries an × that toggles the pending set immediately); an *Add tag* control opens an inline panel inside the section (no overlay layer): a filter input with the catalog `search` glyph as leading affordance; the tag list as `.pick-row` buttons — assigned rows carry the released active state (`data-assigned`, check glyph, `--accent-quiet` ground); the filter marks the matched substring via `matchSegments()` (`.matched` spans in accent); ↑/↓ move a cursor row (`data-cursor`, `moveCursorIndex()` wrapping per the menu convention, the field keeps typing focus, any query change resets the cursor) and Enter toggles the cursor row when one is active, else applies `inlineTagAction()` — joining an exact (case-insensitive) match or creating through the released `library.createTag` path; with no exact match a pinned **Create row** carries the typed name and is activatable by click or Enter (same path, AC-205). Esc closes the picker only; the pending set is owned by the editor until Save. The decision logic lives in `lib/tagpicker.ts` as pure functions (`chipsFor`, `filterTags`, `toggleTagId`, `inlineTagAction`, `matchSegments`, `moveCursorIndex` — the `dragstrip.ts` precedent, DR-424). i18n: the `picker.*` keys and `details.tagCreate`; `details.tagNoMatches` retired with the notice the Create row replaces.
- **Tag-count freshness (D38, AC-201):** `state/library.svelte.ts` re-reads the tag list after a successful `delete()` and after `bulkTags()` (the `updateDocument` pattern), so the Browse submenu counts and the manager's counts match membership immediately after a delete or a bulk tag assignment.
- **Details re-init snapshot guard (D39, AC-206):** the `DetailsModal` re-initialization effect compares the document's own stored values (`title/author/notes/favorite/tags`, serialized) against the last initialized snapshot and returns early when unchanged — external catalog writes (an inline tag creation, a rename of a tag the document does not carry) no longer re-read the pending editor; a real document write (including the rename-follow of DR-267) still re-reads it.
- Filtering: `BrowseMenu.svelte`'s checkable multi-select **Tags** submenu with live counts; the submenu's checked items are one filter display (the chips were removed in v0.0.3); since v0.0.14 the active-filter strip above the document area displays and removes them too ([browsing-and-filtering.md](browsing-and-filtering.md)).
- `NewTagField`: since v0.0.14 the field receives focus when the manager mounts (UI-58 — one `requestAnimationFrame` focus call; typing immediately creates). Enter creates; a duplicate-name `AppError` reopens the field with an inline error and the typed text preserved.
- Bulk: `BulkBar.svelte` → `TagPickerModal.svelte`: two-pane Add/Remove checkbox list pre-ticked from current membership; confirm calls `library_bulk_tags` once.
- The manager's live count is quiet secondary text with tabular figures (v0.0.4, UI-24 unchanged); `chip-cutover.test.ts` still guards the removed pill classes.
- The i18n catalog carries the tag vocabulary in both values and keys (`browse.tags`, `browse.manage`, `tagsDialog.*`, `bulk.tags`, `tag.renameAction`, …); `i18n/coverage.test.ts` and `i18n/terminology.test.ts` assert that no user-facing string contains *category/categories* (AC-113).
