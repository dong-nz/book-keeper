# Reading EPUBs — technical reference

**Since v0.0.9, updated in v0.0.10** · Requirements: FR-22, FR-23 (ADDED), FR-17 (MODIFIED), UI-46, UI-47, UI-48 (ADDED; MODIFIED in v0.0.10 — the ToC panel's pin, shared with UI-49, and the settings control in the window chrome, UI-50), UI-44 (MODIFIED), NFR-09 (extended by AC-138); v0.0.10 decisions DR-327 (the pin lands in this host), DR-337/DR-342/DR-343 (pin semantics), DR-344 (the settings menu host + the reader-window updater capability) · User guide: [features/reading-epubs.md](../features/reading-epubs.md) · Spec: [SPEC-v0.0.9.md](../../specs/SPEC-v0.0.9.md) §2 (FR-22/FR-23, UI-44–UI-48), §3.2–§3.13 (technical design), §4 (AC-132–141) — decisions DR-294…DR-308 (design confirmations and build-time records), DR-300/DR-310 (the AC-138 budgets and their calibration), DR-314/DR-316 (Phase-B reader fixes on the shared surface). The library half of the feature (import acceptance, metadata, covers, rename/relink) is documented in the pages this one cross-links; this document covers the reading product and the EPUB modules.

## What this feature is

An EPUB is a zip container of XHTML chapters + CSS + assets, with a package document (OPF) declaring metadata, the reading order (spine) and optionally a table of contents. The app's chosen architecture (OQ-57 → A, DR-294): **Rust parses and serves, the bundled web engine lays out and displays.** No layout engine is written; no rasterization exists on this path — the PDF reader's cost profile (pdfium + PNG encode, ≈ 90 % of page CPU) has no counterpart here. The reading surface is one mode: continuous vertical flow in spine order, app typography, sanitized author content.

## Modules

### `src-tauri/src/epubmeta/mod.rs` — the package reader (import + open facts)

- `extract(path) -> Result<EpubMeta, AppError>` — the **import-phase** read, two-phase rule (DR-298, §3.12 rule 1): open the zip → validate the `mimetype` entry (exists, content starts `application/epub+zip`; the STORED-first-position rule is not enforced) → parse `META-INF/container.xml` (rootfile) → parse the OPF: first `title` / `creator` by **local name** (accepts `dc:`, `dcterms:` and default-namespace forms; first occurrence wins; whitespace-trimmed; empty → `None`) and `<meta name="cover">` → manifest id → item href → `CoverRef { entry path, declared media-type }` — a reference, never bytes (the cover worker decides pixels, [covers.md](covers.md)). A failed cover lookup yields no `CoverRef` (glyph fallback). A module test places a 70 MiB chapter entry in a valid package and asserts `extract()` succeeds: the import path never opens chapter entries.
- `read_package(path)` — the **reading-phase** read, called only at first open (never by import): spine items (entry, media type, `size` = the zip central directory's `enclosed_size` — never from parsing; an entry missing from the archive stays in the spine with size 0), the ToC tree in the released `OutlineEntry` shape with `page` carrying the **1-based spine index** (source order: EPUB3 nav item → EPUB2 NCX via `<spine toc>` → spine-derived fallback, titles from the percent-decoded entry file-name stem, depth 0; entries resolving outside the spine are skipped), package language (`dc:language` or root `xml:lang`) and direction (root `dir` or `<meta name="dir">`).
- **Zip-bomb guard:** every entry read is bounded at 64 MiB decompressed, checked against the central directory's declared `enclosed_size` before reading — rejection at zero read cost.
- **Href resolution rule** (shared with the sanitizer): strip fragment/query → percent-decode → normalize backslashes → join against the OPF's own directory → dot-segment normalization; a path escaping the archive root is a failed lookup.
- Typed errors: `AppError::EpubUnopenable` (kind `epub_unopenable`) for every unreadable package — not a zip, bad/missing `mimetype`, missing/unparseable container or OPF, size-guard breach. Per the released resilience rule (M17) the import pipeline treats it as the filename-fallback path; the typed error surfaces only when the app is asked to read the package.

### `src-tauri/src/epubsrv/mod.rs` — the delivery pipeline

- `manifest(id, path) -> ManifestDto` — the `app_epub_manifest` payload: `{ spine: [{index, entry, media_type, size}], toc, base_url, language, direction }`. `base_url` platform branch (DR-297/DR-301): Windows → `http://pdfkeeper-epub.localhost/{doc-id}/`, other platforms → `pdfkeeper-epub://{doc-id}/`.
- `serve(doc_id, request_path) -> (bytes, media_type, headers)` — resolves the doc-id through the released `library::service::open_target` first (missing row/file → the same typed errors the reader commands produce, before any file read), then the extension check (`is_epub_path` → `UnsupportedType` for a non-EPUB document), then serves the zip entry:
  - **Media types:** a per-document declared-type map (manifest items, entry → declared `media-type`) is built once per (doc-id, mtime) and held beside the byte LRU; HTML-family entries (declared, or `.xhtml/.htm/.html` when undeclared) are sanitized and served as `text/html`; `image/svg+xml` entries are sanitized too; everything else is served raw — declared type, else an extension map (css/png/jpeg/gif/svg/webp/woff/woff2/ttf/otf/js), else octet-stream.
  - **Sanitizer** (streaming quick-xml reader/writer, O(1) memory, XHTML text kept verbatim): strips `<script>` (including inside inline SVG subtrees), `<iframe>`, `<object>`, `<embed>`; strips every `on*` attribute; drops `javascript:` hrefs; rewrites `src`/`srcset`/`poster`/`href`/`xlink:href` and `url()` tokens (in `<style>` text and `style` attributes) that reference package entries to protocol URLs resolved from the referring entry's location; fragment-only and external `http(s)`/`mailto` references pass through; adds `loading="lazy"` to `<img>`. A `data:` URI in a resource attribute is decoded and re-served as a **synthetic protocol entry** `data/<encoded source-chapter path>/<hash>.<ext>` inserted into the LRU with the chapter (hand-rolled FNV-1a 64-bit hash + base64 decoder — no new dependency, DR-302); the rewrite is required because the released CSP's `img-src` does not admit `data:`.
  - **Bounded LRU** (§3.12 rule 4): keyed (doc-id, entry path, file mtime); caps 32 MiB / 128 entries; mtime change invalidates (rename/relink follow-through). Responses carry `Cache-Control: no-cache`, an ETag from mtime+size, and the probe's CORS headers — measured (DR-297): WebView2 does **not** cache app-defined-scheme responses, so the LRU carries the repeat-read cost.

### Protocol registration (`src-tauri/src/lib.rs`)

`register_asynchronous_uri_scheme_protocol("pdfkeeper-epub", …)` — the handler is a thin wrapper (R1.2 discipline applied to the protocol): it moves the request to a worker thread (R3.5) and calls `epubsrv::serve` through `Db::with`. **Measured URI forms (DR-305):** on Windows wry delivers `pdfkeeper-epub://localhost/<doc-id>/<path>` (the engine-origin request rewritten to the app scheme with authority `localhost`); `parse_request` accepts that form, the scheme-with-doc-id-authority form, and the origin form. Typed errors become **404 with empty body** — a protocol response cannot carry an error payload; the reader window's chapter-error surface handles a failed chapter. Nothing is extracted to disk: reference-in-place holds end to end (verified in the lane: the fixture's image, stylesheet and embedded font arrive through the protocol with no package file on disk).

## Commands (thin wrappers, R1.2)

- `app_epub_manifest(id) -> ManifestDto` (`commands.rs`): resolve through `open_target` (typed errors first), extension check, `read_package`. The released `background(…)` blocking pattern (the `app_pdf_outline` shape). Mirrored in `ui/src/api.ts` + `types.ts`; the router↔client set-equality test holds them in step (AC-41).
- `app_open_reader_window(id)` — **the type branch lives here** (DR-303 item 1): after resolving the target, the window URL is `index.html?reader=<id>&kind=epub|pdf`, the kind derived from the resolved path before the window exists. Same window kind, same create-or-focus rule, same label `reader-<id>` — no new window kind, no extra round-trip. `main.ts` validates the parameter; `ReaderApp` constructs exactly one store (`ReaderStore` or `EpubReaderStore`): no PDF reader machinery ever runs for an EPUB and none for a PDF (AC-125).
- Activation (double-click / `Enter` / the card action) routes an EPUB to `app_open_reader_window` exactly like a PDF (FR-17 MODIFIED, OQ-54 → A); *Open in external viewer* (`app_open_document`, the OS default application) is unchanged for both types.

## Reading UI (`ui/src/ReaderApp.svelte`, `components/EpubReaderView.svelte`, `components/EpubReaderControls.svelte`, `lib/state/epubReader.svelte.ts`)

- **One store per window, flow semantics.** `EpubReaderStore` mirrors the released single-source rule (DR-155): the observed scroll position is the only source for the readout, the ToC current entry and the mount window.
- **Chapter delivery:** the view fetches `base_url + entry` with `fetch()` (the CSP's `connect-src` entries, DR-297); fetched chapter text is deduplicated in the store (the `ReaderStore.images` request pattern); the view parses it with `DOMParser` and mounts it in a **Shadow DOM per chapter** — author `<style>`/`<link>` are scoped inside it and cannot touch the app chrome; author element ids resolve in the chapter's own root; theme tokens and the text-size custom property reach the content through inheritance.
- **Embedded fonts (DR-307/DR-308):** the engine ignores `@font-face` declared in a shadow tree, so the view hoists `@font-face` blocks from delivered CSS (inline and linked, deduplicated per window) into one document-level `<style>` — **only faces whose every `url()` token the delivery rewrote to a protocol URL under the document's own base**; a face naming a remote host stays shadow-scoped, where the engine ignores it: the reading surface addresses no remote host (AC-137). `serve()` rewrites `url()` tokens in CSS assets by the same href rule, resolved from the CSS entry's own directory.
- **Mount window over measured heights:** `$lib/virtual`'s `window()`/`indexAt()` unchanged, `overscan = 1` — the DOM holds viewport ± 1 chapter, never the book. Flow content has no data-derived geometry, so heights are **measured once and kept** across recycling (a recycled chapter renders its header line in a box of its measured height — the scrollbar stays honest); an unmeasured chapter is estimated at 0.03 px per uncompressed byte until first mount; a measured height change above the viewport compensates `scrollTop`. Chapters over 200 000 uncompressed bytes mount in chunks of 250 parsed nodes.
- **Position model:** book percent from **cumulative uncompressed spine-entry sizes** (read once from the zip central directory at open); the live readout `NN % · <chapter label>` interpolates within the current chapter's scroll range; the end-of-book rule (DR-306): once the viewport bottom reaches the last chapter's range end the readout reads 100. The position control opens a jump field — a typed percent resolves to the spine item containing it and lands at its start. `End` scrolls the flow to its bottom (`scrollToEnd`), not the last chapter's start (DR-306).
- **Internal links:** fragment hrefs resolve chapter → manifest id → spine item; an unmounted target mounts first, then the view scrolls to the element id. External `http(s)` links open through the opener plugin's `openUrl` from the frontend (capability `opener:allow-open-url` on `reader-windows.json`, DR-303 item 6 — no new command).
- **Text size:** the ladder `[14, 16, 18, 20, 24, 28]` px, default 18; a global setting key `epub_text_size` (Rust validator `is_valid_text_size` is the authority, mirrored client-side), persisted in `settings`, applied live as a CSS custom property, re-applied through the released `settings_changed` broadcast (DR-303 item 5). The PDF reader's session-only zoom has no EPUB analogue (none invented).
- **ToC panel:** the same `TocPanel` component serves both readers (DR-303 item 7): the flat-depth tree operations moved to shared pure functions both stores call (`tocParentsOf`, `tocVisibleOf`, `isTocParentOf` in `lib/state/reader.svelte.ts`), the `OutlineEntry.page` field carries the target in both (1-based page / 1-based spine index), the current-entry highlight is an optional binding the EPUB strip passes. Present-when-present: a package without any ToC source shows no control (the spine-derived fallback exists in the manifest; the UI rule is unchanged). Control order in the strip: ToC (first when present), position readout, text-size − / +. No view-mode control, no zoom, no page arrows. **Pin (v0.0.10, UI-48 MODIFIED per DR-327; semantics per UI-49 §3.8 and [reading-pdfs.md](reading-pdfs.md)):** the panel's toolbar row carries the shared pin toggle — no per-host branch; pinned, the panel docks at the window's left edge (`TocDocked` in the shared host) and the flow narrows by exactly the panel column: the mounted chapter stays contained and the 68 ch reading-column cap re-wraps in the narrower box (the cap follows the container, verified 612 → 490 px under a simulated narrower window); entry selection keeps the pinned panel open; `Esc` closes the panel first and the docked position is kept; the ToC control hides/re-shows at the same docked position; `tocPinned`/`tocDockedOpen` live on the EPUB store (separated per DR-337, session-scoped per OQ-60/DR-327); unpinning restores the released overlay. The strip's three controls and their order are unchanged.
- **Settings control (v0.0.10, UI-50 host per DR-344):** the shared `SettingsMenu.svelte` renders in the book window's top chrome immediately before `WindowControls` — the same component and the same complete menu as in the library window and the PDF reader (theme cycle live everywhere, *Settings* opens the settings dialog in this window, *Check for updates* works here because `updater:default` joined `capabilities/reader-windows.json`). No reader-window gate remains in `ReaderApp.svelte`.
- **Keyboard (UI-39 semantics, page → flow):** `ArrowUp`/`ArrowDown` one notch, `PgUp`/`PgDn` one viewport, `Home`/`End` book start/end, `Escape` closes the window; the ToC panel follows the released focus/Escape behavior; the reading keys carry no page arrows and no zoom keys (the named exclusions).
- **Typography:** reading column centered, max measure 68 ch; body serif stack, line-height 1.6, left-aligned; the app's reading stylesheet is injected after the author's with `!important` on the typography properties — author layout intent survives, app typography wins. RTL: the package's declared `dir`/language pass through to the flow. Fixed-layout books render as width-normalized continuous blocks — a named limitation.
- **Error surface:** malformed/unrenderable book → the released unrenderable-document path (typed message + *Open with the default app* action, AC-133); missing file → the released missing-document rules; a failed chapter request (protocol 404) shows the chapter-error line, never a silent gap.

## What this feature does not have (stated so nobody builds it by accident)

Full-text search; DRM/encrypted EPUBs (they open with the OS application); page numbers/pagination facts; reading-position persistence; paginated page-turns or spreads; type badges or type filters (UI-47 → A: the library treats documents uniformly); a `doc_type` column (the type is the extension — a derived fact stays derived, R2.1). The FR-20 password plumbing is PDF-only: `pdf_password` is never set for an EPUB.

## Invariants

- Import never pays for reading structures: `extract()` opens only `mimetype`/`container.xml`/OPF; `read_package` runs only at first open.
- Every package read is bounded: 64 MiB per-entry decompressed guard checked against the central directory before reading; sanitized output is bounded by the 32 MiB / 128-entry LRU; the mounted DOM is bounded to viewport ± 1 chapter.
- No package content is ever written to disk by the reading path; no author script runs; no request leaves for a remote host from delivered content (AC-137).
- The window kind is decided by the command on the resolved path; exactly one reader store exists per reader window, and it is the window's only state owner.
- The ToC tree rule has exactly one implementation (the shared pure functions); `OutlineEntry` is one shape serving both readers.
