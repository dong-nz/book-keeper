## Extraction (`src-tauri/src/pdfmeta/`, `src-tauri/src/epubmeta/` since v0.0.9)

- `lopdf` reads the PDF Info dictionary: `/Title` → title, `/Author` → author. Encrypted files, compressed object streams, malformed xref/trailer — all handled by fallback, never by error (FR-05).
- **EPUB (v0.0.9, FR-22/AC-139–AC-140):** `epubmeta::extract` reads the package document (OPF): first `dc:title` → title, first `dc:creator` → author (two-phase read — metadata, then the spine/manifest references the reader needs; the import stores the open facts alongside). A book that declares nothing yields no fields — the same filename fallback as a PDF; a malformed package is a typed error inside the service, which applies the same fallback — **an unreadable file never fails the import batch** (AC-141's import half).
- Fallback: title = filename minus the supported extension (`.pdf`/`.epub` since v0.0.9; `.pdf` before), author empty. A failed extraction never fails the import batch.
- `documents.title_source` (`auto` at import, `user` on any manual edit) gates relink and rename title re-derivation (missing-files-relinking.md, renaming-a-documents-file.md) — the gate is type-independent: a book's auto title behaves exactly like a PDF's.

## Editing

- `library_get_document(id)` / `library_update_document(id, title, author, notes, favorite, category_ids[])` — single transaction; FTS triggers reindex automatically (searching.md).
- Title required (NOT NULL); empty input rejected at the command layer with a typed `AppError` and shown as an inline field error.
- No length caps on title/author/notes in either layer (FR-06: "no length cap in v1"); SQLite TEXT stores what is given.
- Editing changes only the library entry — the file on disk is never renamed (FR-01).

## Editor modal (`components/DetailsModal.svelte`, 560px; UI-02)

- Opened from the row/card Details action or the context menu; one document at a time; loads via `library_get_document`.
- Fields: Title (inline error on empty, modal stays open; while `title_source = auto` and the title is untouched the field carries a quiet "from filename" provenance hint that disappears on the first edit), Author, Notes (textarea auto-growing from 84px, min-height enforced in CSS), favorite toggle; stored path shown in mono under the header. The tags field: a checkbox list + inline new-tag field from v0.0.8 until v0.0.13; **since v0.0.14 a picker** (`TagPicker.svelte` — chips row + inline add-picker with filter, active-state rows, cursor keyboard model, pinned Create row; full design in [tags.md](tags.md) §UI). The pending set, `baselineIds` dirty tracking, and the Save path stay in `DetailsModal` — the picker is props in/out; `DocumentDto.tags` still ships per document (no second query path, R1.6).
- Save closes the modal only after the command resolves — no optimistic write (§5.3.4).
- `Esc` with unsaved changes routes through an inline discard-confirm bar (Keep editing / Discard); focus is trapped by the kit and returns to the opener (DR-45, DR-57).
- Footer actions (completed during stage-4 verification to match UI-02): **Delete** (label without the ellipsis since v0.0.4, UI-20) hands the document to the standard delete confirmation dialog — a completed deletion closes the editor, a cancel does not; **Relink** (rendered only when `missing`, likewise without the ellipsis since v0.0.4) closes the editor and opens the relink dialog, since the editor's snapshot would go stale (missing-files-relinking.md).
- The "from filename" provenance hint described in the spec's UI section was not built; provenance is visible through the title content itself (deviation recorded per Rule 7).

## Display in the library (UI-06, v0.0.2)

- `DocumentRow.svelte` renders, inside the title cell: `.title-line` (single line, full title carried by the tooltip — native `title` until v0.0.6, the shared app `Tooltip` since v0.0.7, UI-37), then `{#if doc.author}` an `.author-line` and `{#if doc.notes}` a `.notes-line` — both ellipsized in CSS and carrying the full text the same way. `DocumentCard.svelte` renders the author line under the title and clamps the title to two lines; **notes are not rendered on cards** (the editor remains their full view). Empty fields render no element and reserve no space — the row height is a function of the data, not a fixed slot with empty gaps.
- **Row heights are data-determined (DR-85; base raised in v0.0.3, OQ-25, and again in v0.0.7, OQ-45/DR-189).** `lib/virtual.ts` keeps `ROW_HEIGHT` (64 from v0.0.3; **88 since v0.0.7** — sorting-and-views.md §3.12) and `ROW_LINE = 18` mirroring the CSS custom properties, and `rowHeight(doc)` = `ROW_HEIGHT + lines * ROW_LINE` where `lines` counts the non-empty author/notes fields (0, 1 or 2 → **88 / 106 / 106 / 124 px** as shipped in v0.0.7; the per-line increment is unchanged through every base change) and `rowOffsets(rows)` builds the prefix-offset array. `window(scrollTop, viewportHeight, offsets, overscan)` and `nearEnd(scrollTop, viewportHeight, offsets, near)` take that array. Windowing stays pure arithmetic with no DOM measurement, and the infinite-scroll prefetch stays correct with mixed heights because the offsets describe the actual layout. The grid no longer has a constant slot: `uniformOffsets(count, cellHeight(cardWidth))` is fed by the derived geometry (sorting-and-views.md), so the row block always equals the cards it contains.
- No truncation happens in Rust: the full strings travel in `DocumentDto` and CSS performs the clamp. The full text of every ellipsized line is offered as a tooltip: the native `title` attribute from v0.0.2 until v0.0.6, and since v0.0.7 the shared app `Tooltip` component (UI-37 — `--surface-1` ground, overlay shadow, the app's ramp rather than the OS theme; the-app-window.md §3.11). Still exactly one tooltip system in the app; only which one these labels use changed.

## Invariants

- `title_source` transitions only auto → user (a manual edit never reverts to auto).
- Extraction failure is silent per file; only the batch result is reported (importing-files.md).

## Change history

- 2026-11-03 (v0.0.1) — First shipped. Migrated from SPEC-v0.0.1-metadata-editing.md, corrected to the verified code: editor Relink…/Delete… footer actions and the "from filename" provenance hint completed during verification (UI-02); notes field auto-grows from 84px; no field length caps (FR-06); delete confirmation title plural-aware ("Delete 1 document?" / "Delete N documents?").
- 2026-11-04 (v0.0.2 — UI-06 ADDED; DR-85) — **Author and notes became visible in the library itself.** List rows render an author line under the title and a notes line below it; grid cards render the author line and clamp the title to two lines (notes stay in the editor); every ellipsized line carries its full text in the native `title` tooltip; empty fields render no element. Because the shipped list virtualized at a fixed 48px slot, row heights became data-determined: `rowHeight` / `rowOffsets` in `lib/virtual.ts` (48 / 66 / 84 px from the base + per-line tokens) feed the windowing functions, which now take a prefix-offset array instead of a constant. No backend or DTO change — the strings were already shipped. Verified by `virtual.test.ts` (heights, prefix sums, windowing over mixed offsets) and the smoke flow `flowMetadataDisplay` (lines, tooltips, measured row height, empty fields, card behavior).
- 2026-11-04 (v0.0.3 — row geometry only, DR-99, OQ-25) — **The metadata display design is unchanged; its base moved.** Author and notes lines, the CSS clamp with native `title` tooltips, the no-element-no-space rule for empty fields, the card's author line and the "notes stay in the editor" rule are the v0.0.2 behavior. The editor's entry point moved into the row's hover-revealed actions line with the `info` glyph (opening-and-deleting.md); `DetailsModal.svelte`, `library_get_document`, `library_update_document`, `pdfmeta` extraction and the `title_source` gating are untouched — the Rust tests here are the same tests as in v0.0.2.
