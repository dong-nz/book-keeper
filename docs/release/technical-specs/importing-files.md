## Commands (Tauri)

| Command | Signature | Behavior |
|---|---|---|
| `library_import_paths` | `(paths: Vec<String>, tag_ids: Vec<i64>) -> ImportResult` | Imports the given supported-document paths (`.pdf` and `.epub`, extension-based and case-insensitive since v0.0.9 — `library::is_document_path`); unsupported extensions, directories and unreadable paths are reported as skipped (plain paths since v0.0.9; the typed `Skipped` enum is gone), never silently dropped. `tag_ids` is the whole active filter set (v0.0.2; was `category_id: Option<i64>`) — an empty vector assigns nothing |
| `library_import_folder` | `(dir: String, tag_ids: Vec<i64>) -> ImportResult` | Walks `dir` for `*.pdf` and `*.epub` (`std::fs::read_dir`, one-time bulk; nothing is watched; both types collected by the same walk since v0.0.9, AC-126) |

`ImportResult { imported: i64, skipped: Vec<String> }` — `skipped` carries the skipped paths (v0.0.9: one list for unsupported kinds, duplicates and unreadable paths; the UI reports the duplicate case in its own toast wording). Progress is streamed on the `library_job_progress` event (`{kind: "import", processed, total, done}`); the command returns once rows are committed — cover generation is queued separately (covers.md), so import never waits for rendering (NFR-02).

## Pipeline (`src-tauri/src/library/service.rs`)

**As re-cut in v0.0.7 (§3.20, DR-233).** The released single-transaction pipeline held the library's one Mutex-guarded connection for the whole import while it extracted metadata per file — synchronous commands (search, categories, settings) blocked on that mutex for the run, and progress was emitted only per 500-file chunk, so imports of ≤ 500 files showed no progress at all. The shipped pipeline:

1. Candidates: filter paths to the supported document types — `is_document_path` (extension `.pdf` or `.epub`, case-insensitive; v0.0.9, UI-46/AC-126; before it: `.pdf` only) — `normalize_path`, metadata (size/mtime) per file — **outside the connection**.
2. **Chunked work:** `CHUNK: usize = 5` (v0.0.8, D25); for each chunk: metadata extraction per file by type — `.pdf` → `pdfmeta::extract` unchanged, `.epub` → `epubmeta::extract` (the two-phase package reader, [reading-epubs.md](reading-epubs.md)) — outside the lock; a per-file extraction failure falls back to the filename silently — never fails the batch (both types, FR-05/AC-140). Then `import_chunk` inside **one short transaction** (`db.with_raw`): INSERT OR IGNORE + join rows for the active tags. The connection is held only for the write, never for extraction — synchronous commands keep answering between chunks (AC-101).
3. **Duplicates (FR-11):** `documents.path UNIQUE` + `INSERT OR IGNORE` — ignored rows are collected as skipped. Semantics unchanged across the v0.0.9 type extension.
4. **Auto-assignment (FR-10, v0.0.2):** `validate_tags` checks **every** id before the first chunk writes (`AppError::TagNotFound`; the id type is `tags` since the v0.0.8 rename); join rows are written per chunk inside the same transaction as that chunk's documents — one assignment set per import. An empty slice assigns nothing.
5. **Progress:** one `library_job_progress` `{kind: "import", processed, total, done}` event opens the run before any file is processed (`processed: 0`), one per chunk, a final `done` event closes it — emitted outside the lock. Visible from start to completion for imports of any size (AC-101).
6. Cover jobs enqueued to the cover queue (covers.md) as rows commit; the command returns once the last chunk is committed — import never waits for rendering (NFR-02).

## UI (`ui/src/`)

- `components/ImportButton.svelte` — **deleted in v0.0.3** (UI-14; R7.4). It was a split control: primary opened the native multi-select picker (`tauri-plugin-dialog`), the caret opened a hand-written menu with "Import folder…", and while a job ran both halves were disabled with the label "Importing…". Its whole role moved into the search field, below.
- `components/SearchBox.svelte` (v0.0.3, UI-14) — the field keeps its leading magnifier and carries, at its trailing end behind a 1px `--border-strong` divider, the import control: a plus icon button (`plus` path already in `components/icons.ts`; no new icon) with the accessible name and tooltip "Import". The clear button and the plus share that slot — clear while the field holds text, plus otherwise — so a control is never hidden by a state the user can't see. The plus opens a two-item menu, *Import files* and *Import folder* (labels without the ellipsis since v0.0.4, UI-20), reusing the shipped menu chrome, and both call the existing `importFlow` functions (`pickFilesAndImport`, `pickFolderAndImport`). `Ctrl+I` and the drag-and-drop path are untouched. The busy state moved with the control: the plus is disabled while `feedback.job !== null`.
- `App.svelte` subscribes to `tauri://drag-enter` / `drag-leave` / `drag-drop` (real FS paths; `drag-over` is not subscribed — enter/leave is sufficient for the overlay) and renders the full-window drop overlay. Since v0.0.2 its second line names **every active tag** (`drop.toCategory` = "Adds to {tags}", built from `filter.tag_ids`) — in v0.0.1 it named the single selected category. Since v0.0.9 the overlay accepts mixed drops: PDF and EPUB files in one gesture, unsupported files land in the skipped list.
- `lib/importFlow.ts` — picker calls; since v0.0.9 the file picker's filter is `DOCUMENT_FILTERS` = one "Documents" entry accepting `pdf` + `epub` (UI-46; one filter entry, not two, so a mixed selection is one dialog). `state/library.svelte.ts#importPaths` — invoke + result reporting: toast "Imported N file(s)" (wording generalized in v0.0.9, DR-304 — the message names what it actually did) plus, when `skipped` is non-empty, a second toast "{count} documents skipped (already in library)". The spec's single-toast-with-expandable-body detail was not built; two plain toasts carry the same information (deviation recorded here per Rule 7).
- `ProgressBar` in the status bar renders `library_job_progress`; the busy gate (Rescan and Import disabled) stays closed until the cover queue drains (FR-15; verified: gate opens only after covers complete).

## Invariants

- Import never copies/moves/renames user files (FR-01).
- A failed per-file metadata step never fails the batch (fallback path).
- The same path cannot exist twice in `documents` (UNIQUE).
