### 3.2 Tag picker in Details (UI-02)

New component `ui/src/components/TagPicker.svelte`, mounted in the Details tags section in place of the checkbox list. Props: the current tag ids (bound), the tag catalog (`library.tags`), and mutation callbacks; the pending set, `baselineIds` dirty tracking and Save stay in `DetailsModal` unchanged (F1). Shape: chips row (each chip: name + × button, `aria-label` from the i18n key); a `+ Add tag` control; the add-picker is an **inline expandable panel inside the section** (not a new overlay layer). (Revised 2026-11-20, DR-437 — the user's picker design review; the list half is rebuilt, everything else stands:) the filter input (its own `aria-label`) carries the catalog `search` glyph as a leading affordance; the tag list renders as **rows** in the released list-row language (`--row-control-height`, `--radius-control`, `--surface-2` hover ground — the TagRow conventions, not UA checkboxes), filtered by a case-insensitive substring over the tag name with the **matched substring marked** in `--accent` (color-only, no highlight ground); membership is a **state, not a checkbox**: assigned rows carry a leading `check` glyph, `--accent-hover` text on the `--accent-quiet` ground (the D11 active language); activating a row (click anywhere in it) toggles the pending set. When the trimmed query has **no exact match** (`inlineTagAction` kind `create`), a **Create row** is pinned above the list — `plus` glyph + `t("details.tagCreate")` with the typed name — activating it runs exactly the Enter path; when the query is empty or exactly matches, no Create row; the passive no-matches notice is removed with the checkbox list (its catalog key retires). **Keyboard:** while the picker is open the field keeps typing focus; ↑/↓ move a **cursor row** (pure helper `moveCursorIndex`; cursor ground = hover ground + hairline, `data-cursor` attribute; any query change resets the cursor); Enter prefers the cursor row — with a cursor active it toggles it, otherwise it keeps its released join/create meaning; Escape closes the picker first (the keydown is consumed before the dialog's Escape handler) — the modal stays open; opening the picker and toggling rows never touches the document until Save. i18n keys for the picker controls enter the catalog (R4.1); `details.tagNoMatches` retires with the notice. Pure logic (filter narrowing, chip diff, inline-create decision, match segments, cursor movement) lives in `ui/src/lib/tagpicker.ts` so the units drive it directly (the `dragstrip.ts` precedent, DR-424).

### 3.6 Active-filter strip (UI-09)

New component `ui/src/components/FilterStrip.svelte`, mounted in `DocumentArea.svelte` above the virtualized scroll container, rendered only in the library window and only when a browse filter is active (mode ≠ all, or `filter.tag_ids.length > 0` — F11). Derivation is read-only from `library.filter`; chips carry the same labels the Browse menu uses (i18n keys reused). Each × calls `setFilter` with only that element removed (a tag chip removes that tag id; a mode chip resets the mode to all, leaving tag filters — and vice versa); *Clear all* calls `setFilter({ mode: "all", tag_ids: [] })`; search is never read or written. Overflow: the strip renders one row; a pure helper `overflowChips(counts, widths, available)` in `ui/src/lib/filterstrip.ts` decides, from measured chip widths, how many chips render inline and how many collapse into the `+N` control; `+N` opens a kit `DropdownMenu` (the released menu chrome) listing the hidden filters each with its removal action. The strip never adds a filter (no chooser affordance), never appears with no active filter, and leaves `last_filter` persistence and the status-bar result count untouched. The Browse menu is unchanged in structure and behavior (its checked items remain the filter's display in the menu).

### 3.11 Details re-init guard (D39, DR-438)

The re-initialization effect in `DetailsModal.svelte` writes the form from the stored document, but its body reads `library.tags` (through `idsForNames`), so the tag catalog is a tracked dependency: an **inline creation from the picker** writes the catalog and re-runs the effect — silently discarding the pending editor (the tag joined moments earlier, and any edited title/author/notes/favorite). Found by the redesigned `flowTagsMulti` lane during the build; the v1 lane passed only because its Save expectations coincided with the reset state.

Fix (the user's A decision): the effect keeps its released behavior — re-read the form when the **document's own stored values** change (the rename-follow of DR-267 included) — and adds a snapshot guard: it compares `doc.title/author/notes/favorite/tags` against the last initialized snapshot and returns early when they are unchanged. External catalog writes (create, and a rename of a tag the document does not carry) then leave the pending editor untouched; a real document write still re-reads it. The rename-while-open case (the document's own tag names change) re-initializes by design — the editor follows the document.

Test: AC-206's lane half — a drafted title edit plus a joined tag survive two inline creations and reach the Save payload.
